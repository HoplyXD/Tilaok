# NLB-P00-T02 — Protocol and measurement contract v1

**Version:** wire major 1, minor 0 (documentation contract; not implemented)
**Status:** approved target contract for later implementation, subject to the separately gated NLB workstream.
**Canonical product rules:** [NETWORKED_LIVE_BUILD.md](../../../NETWORKED_LIVE_BUILD.md).
**Baseline:** [baseline and target decisions](baseline-2026-10-19.md).

This document resolves wire representation, bounds, validation outcomes, recovery, and measurement definitions for NLB implementation tasks. It defines future behavior only. None of these validators, transports, targets, or benchmark results exist in the current executable.

## 1. Wire framing, encoding, and common bounds

Use a fixed little-endian binary envelope with bounded message-family payloads. Do not use Godot `Object`/`Variant` deserialization, arbitrary dictionaries, unbounded JSON, or client-controlled class/resource paths on the wire. Every integer is unsigned unless explicitly signed; strings are UTF-8 without NUL; lengths count encoded bytes.

| Envelope field | Encoding | Rule |
|---|---:|---|
| Magic | 4 bytes | ASCII `TILK` |
| Protocol major / minor | 1 byte each | Major mismatch rejects. Minor mismatch is accepted only when the peer advertises support for every required feature bit. |
| Message family | 1 byte | Enumerated below; unknown family rejects. |
| Flags | 1 byte | Reserved bits must be zero. |
| Session epoch | uint64 | Zero only for discovery query/beacon. Otherwise exact current epoch. |
| Family sequence | uint32 | Separate sequence space by session epoch, authenticated peer, direction, and family. |
| Payload length | uint16 | Must equal remaining frame bytes exactly. |

The envelope is **22 bytes**. Maximum complete application frame is **900 bytes**, including envelope and family payload. This is the unfragmented UDP application payload limit; IP/UDP/ENet framing and retransmission overhead are excluded from this 900-byte limit and must be measured separately. No protocol frame may depend on IP fragmentation. Discovery beacon/query frames have the stricter 256-byte complete-frame limit.

Common caps: four seats; 16 protocol feature bits; 24 UTF-8 bytes for a requested display label; 32 ASCII bytes for map/content IDs; 48 ASCII bytes for item/variant IDs; 13 uppercase Base32 characters for Lobby ID; 64 entries per bounded ID list; 48 persistent stage entities (matches current `item_persistent_cap`); 16 projectiles, 4 bubbles, 32 VFX (current offline tuning caps); 32 event markers; 128 score/outcome ledger entries; and 32 pending request results per peer. A host profile whose content exceeds a hard wire cap fails compatibility/lobby readiness with `CONTENT_LIMIT_EXCEEDED`; it must not silently truncate state. Values inherited from offline tuning may change only through a versioned contract update and dependent test/document updates.

All strings use a uint8 byte length followed by bytes, with the per-field maximum above. All arrays use a uint16 element count followed by fixed-width or individually bounded entries; validate the count before allocation. Enums are uint8 or uint16 as stated by family and unknown values reject. Coordinates are signed int32 logical-grid cells or signed fixed-point int32 world units; never send floating-point coordinates. If a float is required in a future schema, reject NaN, infinity, and values outside its declared range before gameplay code.

## 2. Identity, epochs, sequences, and credentials

| Identity | Representation and lifetime | Security / reset rule |
|---|---|---|
| Lobby ID | 64-bit random value, rendered as 13 unambiguous Base32 characters. | Public discovery lookup only; never authenticates or grants a seat. |
| Session epoch | 64-bit cryptographically random nonzero value per host session. | Changes on host session restart and replay. All old callbacks, packets, requests, and tokens become stale. |
| Peer ID | Transport-assigned ENet peer ID, uint32. | Temporary connection handle only; never persisted or accepted from payload as seat authority. |
| Player ID | Host-assigned random 128-bit value. | Stable across that player's reclaim reservation; is not a real name or account. Not accepted from unauthenticated input. |
| Seat ID | uint8 in 0..3. | Derived from host-side peer ownership after authentication; clients cannot request or assert ownership by supplying it. |
| Match ID | uint64 monotonic counter scoped to session epoch, starts at 1. | New value on a new match/replay; callbacks must match current value. |
| Round ID | uint32 monotonic within Match ID, starts at 1. | Sudden Death uses a distinct attempt ID and does not create a Pugad/round item. |
| Attempt ID | uint16, starts at 0 per round; incremented on retry/recovery attempt. | New attempt invalidates outstanding results/snapshots from the prior attempt. |
| Stage version | uint32 monotonic within session, starts at 0. | Increment exactly once for each committed terrain mutation batch. No wrap during a session; stop before exhaustion. |
| Entity ID | uint64 monotonic host allocator within session epoch. | Never reused within epoch, including after removal. |
| Snapshot ID | uint32 monotonic within session epoch. | Identifies one consistent snapshot and its chunks/ack; not reused before epoch reset. |
| Request ID | uint64 client-generated monotonic value per peer/session/family, starts at 1. | Retry repeats the same ID and identical payload. Host caches the original terminal response. |
| Access token | 128 random bits, single-use, expires 300 seconds after invitation creation. | QR only; redact from logs. Lobby ID is not a token. |
| Reclaim token | 128 random bits, bound to Player ID and reserved seat; rotates after successful reclaim. | Secret, constant-time compare; never log or echo. Old token is revoked on rotation. |

Do not send either bearer token in a join/reclaim packet. Host issues a fresh 16-byte challenge with a 30-second expiry. Client proves possession with `HMAC-SHA-256(token, "TILK-AUTH-v1" || session_epoch_u64 || client_nonce_16 || server_nonce_16 || auth_context_u8 || protocol_major_u8 || protocol_minor_u8)`. Compare all 32 proof bytes in constant time. `auth_context` distinguishes join from reclaim. A challenge is single-use; an exact retry of an already completed nonce returns the cached decision, while a changed proof for that nonce rejects. The host rotates the reclaim token after successful reclaim.

This v1 contract assumes a trusted local LAN and does not provide traffic confidentiality or protection from an active packet-sniffing LAN adversary. Never claim end-to-end encryption. If the threat model expands beyond the approved local-LAN scope, authenticated encryption requires a separately reviewed contract change.

Sequences are uint32. A sequence is newer iff signed 32-bit subtraction `(new - old) > 0`; exactly half-range difference is invalid/ambiguous. A sender must not advance by 2^31 or more without an accepted packet. Sequence state resets only with a new session epoch; per-snapshot input eligibility begins at sequence 0 for the new authenticated peer generation. Request de-duplication is keyed by `(session_epoch, peer_generation, family, request_id)`, stores at most 32 results per peer for 120 seconds, and evicts the oldest completed entry only. If the cache is full of in-flight requests, reject a new request with `REQUEST_CAPACITY`; never evict an in-flight ID. The same ID with a different payload rejects as `REQUEST_ID_REUSE`.

## 3. Transport, channels, ordering, and common validation

The target transport remains Godot high-level multiplayer over ENet after a separately verified engine decision. Use three independent delivery channels so reliable control cannot queue-block input or state: channel 0 reliable ordered control; channel 1 unreliable sequenced input; channel 2 unreliable sequenced state. Discovery uses LAN UDP datagrams before ENet connection. Do not assume order across channels. Terminal ledger, terrain commits, placement results, pause/session lifecycle, and admission use channel 0. Continuous input and superseding actor state use channels 1 and 2 respectively.

Per-message caps and sender state are in §4. Additional common rules:

1. Validate frame length, magic, version, family, reserved flags, exact payload length, and receive rate before decoding fields. Reject before allocating arrays or mutating session/gameplay state.
2. Derive peer, player, and seat identity from the authenticated ENet connection and host registry. A payload identity mismatch rejects as `OWNERSHIP`; never use payload `seat_id` to grant ownership.
3. Validate session, match, round, attempt, stage, snapshot, phase, bounds, enum, inventory, and request freshness before invoking gameplay code. Host simulation boundary is the only mutation point.
4. Input axes are finite signed int16 normalized units in `[-1000, 1000]`. Out-of-range values reject the entire sample as `FIELD_RANGE`; they are **not clamped**. Missing or stale valid input is replaced with neutral state after 150 ms.
5. Unknown enum, wrong field type/width, invalid ID, invalid cell/rotation, NaN/Infinity, oversized field/frame, incompatible content, wrong phase, invalid inventory, unauthorized sender, stale epoch/round/stage, or excess rate is rejected. No malformed message may crash the host.
6. Rejection payloads carry only a uint16 reason enum, family, request ID when available, and current authoritative version. Never echo client strings, tokens, arbitrary bytes, or raw invalid values.
7. Maintain saturating counters by peer/family/reason. Log at most 10 detailed rejections per peer per minute; thereafter log one aggregate per minute. Three authentication/ownership failures in 10 seconds or 120 rate/format violations in 10 seconds closes that peer; one invalid packet alone does not.
8. A disconnected peer is immediately neutralized by the transport callback/input timeout. Later callbacks must match the current session, peer generation, match, round, attempt, and request IDs before acting.

## 5. Snapshot consistency and state recovery

| State class | Authority | Snapshot / update representation | Update and recovery rule |
|---|---|---|---|
| Session, seats, phase, host pause, match/round/attempt | Host | Full lobby/session snapshot; reliable lifecycle events; versioned deltas. | Admission and every phase transition are reliable. Reclaim requires current snapshot ack before input. |
| Actor position, velocity, lifecycle, capture, forces and support-relevant state | Host simulation | Full actor state in snapshot; complete latest per-actor state records in deltas with tick/revision. | No physics lockstep. Newest complete state supersedes older; periodic host state samples repair loss. |
| Persistent construction, edits, removals, stage version | Host placement commit | Snapshot includes complete entity manifest; reliable stage-versioned edit batches. | Version is contiguous; duplicate is idempotent. Any gap pauses client edit-dependent actions and requests full snapshot. |
| Moving/physics blocks and support | Host simulation | Snapshot contains transforms, velocity, path/phase, support/collapse state; deltas contain full latest record. | Client presentation interpolation only. Snapshot repairs missed state; terminal/collapse/removal also reliable. |
| Projectiles, bubbles/captures, bounded transients and VFX | Host simulation | Snapshot includes only live, bounded gameplay transients; deltas include full state and expiry tick. Cosmetic VFX may be recreated locally only if non-gameplay. | Host tick expiry; state samples refresh; missing required gameplay entity or unknown captive reference requests snapshot. Caps match §1. |
| Event schedule, clocks, markers, active commands and deadlines | Host event controller | Snapshot includes locked schedule, current event state, authoritative ticks and markers; reliable event boundaries. | Clients derive display time from host tick. No client countdown or RNG can commit outcomes. |
| Barya placement, carrier, drop/recovery and secured receipt | Host objective/score ledger | Snapshot objective state and carrier; reliable pickup/drop/secure receipt and ledger event. | De-duplicate by objective/event ID; normal capture and score rules remain in GDD/activation contract. |
| RNG decisions and stream identity/state | Host seeded streams | Snapshot includes stream identity, seed/state required to continue approved design and committed decision IDs. | Clients never choose outcomes. Each decision has stable host event ID; repeated event does not consume another draw. |
| Terminal ledger, awards, exact scores, sudden death and match teardown | Host lifecycle/score ledger | Complete ledger in snapshot; reliable exactly-once outcome revisions. | Client deduplicates by `(match_id, round_id, attempt_id, event_id)` and ledger revision; results snapshot repairs missing events. |

Snapshot transfer has one consistency point `(session_epoch, match_id, round_id, attempt_id, host_tick, stage_version, snapshot_id)`. The host captures a consistent state at a simulation boundary. Any subsequent reliable terrain/outcome events and state deltas reference the snapshot ID and carry later authoritative versions. The client buffers at most 256 post-snapshot reliable state events and 2 seconds of state deltas while assembling; exceeding either cap aborts the transfer and restarts once from a newer boundary. The host sends `SNAPSHOT_END` only after every chunk is queued. The client validates length/checksum, installs atomically, applies buffered events in version order, sends ack, and only then may send input. Duplicate chunks with identical bytes are ignored; duplicate index with different bytes aborts. On two consecutive snapshot failures, the host rejects join/reclaim with `RESYNC_FAILED` and disconnects safely.

## 6. Abuse and contract-review examples

These are **DOCUMENT / CONTRACT REVIEW** cases for this P00 document, not executed network tests.

| Case | Example | Contract outcome |
|---|---|---|
| Valid boundary | 55-byte input frame (22-byte envelope + 33-byte input payload), axes exactly -1000 or +1000, current epoch/round and next uint32 sequence. | Accept; process using host-owned peer/seat mapping. |
| Maximum frame | Final full-snapshot chunk frame is exactly 900 bytes (22-byte envelope + 20-byte chunk header + 858-byte chunk); a 65,536-byte snapshot uses 77 chunks, with 76 full chunks and one 328-byte final chunk. | Decode only if family schema, exact length/count/checksum, and every nested cap pass. |
| Over-limit | 901-byte frame; 257-byte discovery beacon; 65,537-byte snapshot claim; 78 chunks for a full 65,536-byte snapshot; a 49th persistent entity beyond current configured cap. | Reject before allocation/state change with bounded reason/counter; oversized current stage blocks compatibility/snapshot, never truncates. |
| Malformed | Wrong payload length, unknown family/enum, reserved flag set, invalid UTF-8, array count beyond cap, NaN in a future float field. | Reject frame/field; no raw payload echoed; repeated abuse follows disconnect threshold. |
| Stale | Prior session epoch, old round/attempt, old stage version, or older sequence. | Ignore or return bounded `STALE_STATE`; never mutate or roll back. |
| Duplicate | Same placement/request ID and identical payload after lost result. | Return cached original result; no second commit, item use, score, or RNG draw. |
| Reused ID | Same request ID with a changed payload. | Reject `REQUEST_ID_REUSE`; rate-count and retain original result. |
| Unauthorized | Peer sends another Player ID, a seat number, client position, score, or host-only pause. | Reject `OWNERSHIP` / `HOST_ONLY`; retain server-side peer ownership. |
| Recovery gap | Client observes stage `V+2` while at `V`, or unknown required entity reference. | Stop dependent predictions/actions; request one full snapshot; controls resume only after matching ack. |
